04 / AS ESCOLHAS DA ARQUITETURA

Mais agentes.
Melhor resposta?

Não necessariamente. Dividir responsabilidades pode ajudar, mas cada nova conexão também tem um custo. Compare as escolhas, não apenas o número de agentes.

Tendências gerais; os resultados dependem da tarefa e da implementação.

05 / DA IDEIA À DECISÃO

O time certo
para cada tarefa.

Antes de escolher um framework, entenda o problema. Abra os cenários para explorar qual abordagem pode fazer sentido.

01Investigar um incidente em várias frentesOrquestração+

Logs, mudanças de código e impacto no produto podem ser investigados separadamente e reunidos depois. Especialistas ajudam quando há subtarefas independentes e critérios claros de entrega.

O cuidado: manter evidências rastreáveis, resolver conclusões conflitantes e limitar tentativas. Uma resposta consolidada ainda precisa de validação.

02Resumir um documento ou tirar dúvidasAgente único+

Se a tarefa cabe em um contexto e usa poucas ferramentas, um agente pode conduzir tudo. Para um resumo simples, uma única chamada ao modelo pode bastar.

O cuidado: verificar se as respostas refletem o documento e se as fontes estão disponíveis.

03Aplicar regras fixas a dados estruturadosAutomação+

Validar campos obrigatórios ou gerar um relatório com uma consulta conhecida não exige decisões abertas. Um script ou fluxo determinístico costuma ser mais simples de testar.

O cuidado: tratar exceções explicitamente. Se as regras já resolvem o problema, um modelo pode ser desnecessário.

01 / O QUE É NECESSÁRIO?

Quatro peças. Papéis diferentes.

Modelo de IA

Recebe uma entrada e gera uma saída. É o motor de linguagem, não o fluxo inteiro.

Agente

Usa um modelo, instruções e contexto para decidir ações dentro de um papel. Pode acionar ferramentas.

Ferramenta

Executa uma operação: somar preços, consultar um arquivo ou buscar dados.

Orquestrador

Define quem trabalha, em qual ordem e com quais informações. Reúne os retornos.

Você não precisa instalar tudo. Para começar abaixo, basta Python 3 e um editor de texto. LangGraph e CrewAI são alternativas para organizar fluxos mais elaborados.

03 / CRIE SEU PRIMEIRO ORQUESTRADOR COM PYTHON

Primeiro a coordenação. Depois o modelo.

No exemplo inicial, “especialistas” são funções com regras fixas. O código é funcional, mas não contém agentes de IA: serve para aprender a dividir o trabalho e transmitir resultados.

  1. Instale Python 3 pelo site oficial.
  2. Baixe o arquivo abaixo e abra um terminal na pasta onde o salvou.
  3. Execute python jantar.py. No macOS/Linux, use python3 se necessário.
JANTAR.PY · EXECUTÁVEL SEM IA
Baixar .py ↓
"""Fluxo funcional sem IA. Valores em reais inteiros, todos fictícios."""
import json


def cardapio(contexto):
    """Especialista 1: recebe convidados e preferência, não o pedido inteiro."""
    pessoas = contexto["pessoas"]
    vegetariano = contexto["vegetariano"]
    return {
        "prato": "Massa com tomate" if vegetariano else "Frango com arroz",
        "comida": pessoas * (20 if vegetariano else 25),
        "bebidas": pessoas * 5,
    }


def orcamento(plano, limite):
    """Especialista 2: depende do plano e usa uma soma como ferramenta."""
    total = sum([plano["comida"], plano["bebidas"]])
    return {"total": total, "saldo": limite - total, "cabe": total <= limite}


def validar(pedido):
    if type(pedido["pessoas"]) is not int or pedido["pessoas"] < 1:
        raise ValueError("Informe um número inteiro positivo de pessoas.")
    if type(pedido["limite"]) is not int or pedido["limite"] < 0:
        raise ValueError("O limite deve ser um inteiro não negativo.")
    if type(pedido["vegetariano"]) is not bool:
        raise ValueError("Vegetariano deve ser True ou False.")


def orquestrar(pedido):
    """Coordena a ordem, distribui contexto e reúne os dois resultados."""
    validar(pedido)
    contexto = {"pessoas": pedido["pessoas"],
                "vegetariano": pedido["vegetariano"]}
    plano = cardapio(contexto)
    # Esta chamada só acontece depois de obter as estimativas do cardápio.
    conta = orcamento(plano, pedido["limite"])
    return {"cardapio": plano, "orcamento": conta}


if __name__ == "__main__":
    pedido = {"pessoas": 6, "limite": 180, "vegetariano": True}
    print(json.dumps(orquestrar(pedido), ensure_ascii=False, indent=2))
O QUE VOCÊ DEVE VER

Com o pedido do arquivo: massa com tomate, comida R$ 120, bebidas R$ 30, total R$ 150, saldo R$ 30 e cabe: true. A saída é um dicionário em formato JSON.

Troque limite por 100: o total continua R$ 150, mas o saldo vira −R$ 50 e cabe fica false. O orquestrador deve mostrar o limite excedido, não esconder a diferença.

CÓDIGO FUNCIONAL · REQUER OLLAMA E UM MODELO LOCAL

Agora o modelo escolhe o prato e comenta a conta em duas chamadas separadas. As funções assumem papéis de especialistas, mas o fluxo ainda é fixo: não há um ciclo autônomo de planejamento e uso de ferramentas.

A soma permanece em Python. O retorno do cardápio é validado; o comentário do modelo precisa de revisão e pode estar errado.

  1. Mantenha jantar.py e jantar_ollama.py na mesma pasta.
  2. Instale e abra o Ollama. Em instalações sem serviço ativo, execute ollama serve em outro terminal.
  3. Baixe o modelo com ollama pull llama3.2:1b. Confira a licença e a ficha do modelo. O download ocupa disco; a execução usa memória e pode ser lenta.
  4. Execute python jantar_ollama.py. A resposta vem do modelo local e pode variar. Se houver erro, o programa interrompe e explica como verificar o ambiente.
JANTAR_OLLAMA.PY · INTEGRAÇÃO OPCIONAL
Baixar .py ↓
"""Evolução local com duas chamadas reais ao Ollama, quando instalado.

Salve junto de jantar.py. Execute: python jantar_ollama.py
Não é um agente autônomo: a sequência continua definida pelo código.
"""
import json
import sys
from urllib.error import URLError
from urllib.request import Request, urlopen
from jantar import cardapio, orcamento, validar

MODELO = "llama3.2:1b"  # Baixe antes: ollama pull llama3.2:1b
ENDERECO = "http://127.0.0.1:11434/api/chat"


def consultar(instrucoes, contexto, formato=None):
    """Acesso ao modelo local; nenhuma chave ou pacote Python é necessário."""
    dados = {
        "model": MODELO,
        "stream": False,
        "messages": [
            {"role": "system", "content": instrucoes},
            {"role": "user", "content": json.dumps(contexto)},
        ],
    }
    if formato:
        dados["format"] = formato
    requisicao = Request(ENDERECO, data=json.dumps(dados).encode("utf-8"),
                         headers={"Content-Type": "application/json"})
    with urlopen(requisicao, timeout=180) as resposta:
        texto = json.load(resposta)["message"]["content"]
    if not isinstance(texto, str) or not texto.strip():
        raise ValueError("O modelo não devolveu texto utilizável.")
    return texto


def agente_cardapio(contexto):
    formato = {"type": "object", "properties": {
        "prato": {"type": "string", "enum": ["massa", "frango"]}},
        "required": ["prato"], "additionalProperties": False}
    texto = consultar(
        "Escolha massa ou frango. Se vegetariano for true, escolha massa. "
        "Responda em JSON com apenas a chave prato.", contexto, formato)
    escolha = json.loads(texto)
    if not isinstance(escolha, dict):
        raise ValueError("O modelo deve devolver um objeto JSON.")
    prato = escolha.get("prato")
    if prato not in ("massa", "frango"):
        raise ValueError("Prato fora do catálogo fictício.")
    if contexto["vegetariano"] and prato != "massa":
        raise ValueError("A resposta ignorou a preferência vegetariana.")
    # Os preços continuam nas regras locais, não são inventados pelo modelo.
    return cardapio({"pessoas": contexto["pessoas"],
                     "vegetariano": prato == "massa"})


def agente_orcamento(plano, limite):
    conta = orcamento(plano, limite)  # Ferramenta determinística faz a conta.
    comentario = consultar(
        "Explique em uma frase se o plano cabe, usando o campo cabe. "
        "Não acrescente preços nem altere valores. Responda em português.",
        {"plano": plano, "limite": limite, "conta_verificada": conta})
    return {**conta, "comentario_do_modelo_para_revisar": comentario}


def orquestrar_com_modelo(pedido):
    validar(pedido)
    plano = agente_cardapio({"pessoas": pedido["pessoas"],
                            "vegetariano": pedido["vegetariano"]})
    conta = agente_orcamento(plano, pedido["limite"])
    return {"cardapio": plano, "orcamento": conta}


if __name__ == "__main__":
    try:
        pedido = {"pessoas": 6, "limite": 180, "vegetariano": True}
        print(json.dumps(orquestrar_com_modelo(pedido),
                         ensure_ascii=False, indent=2))
    except (URLError, TimeoutError, OSError, ValueError, KeyError, TypeError) as erro:
        print(f"Execução interrompida: {erro}", file=sys.stderr)
        print("Confira o Ollama aberto e o modelo baixado. "
              "Se o retorno for inválido, revise-o antes de tentar novamente.",
              file=sys.stderr)
        sys.exit(1)

A página apenas mostra e oferece o código. Ela não executa Python nem chama seu Ollama. O exemplo usa o endpoint oficial /api/chat; a escolha estruturada segue a documentação de saídas estruturadas.

Como evoluir para agentes mais autônomos? +

Adicione uma decisão do modelo sobre qual ferramenta usar, valide seus argumentos e devolva o resultado ao modelo. Limite as repetições e registre o que ocorreu. Em LangGraph, etapas e dependências podem virar nós e conexões; em CrewAI, papéis e tarefas organizam a colaboração.

Não basta renomear uma função como agente. Defina quais decisões o modelo pode tomar, quais operações exigem aprovação e como você vai verificar a resposta. Comece avaliando poucos casos conhecidos.

04 / GRATUITO OU PAGO?

O software pode ser gratuito. A execução tem limites.

Comparação entre modelos locais e APIs na nuvem
Na práticaLocal · OllamaAPI · Gemini
ComeçarInstalar e baixar um modelo com licença adequada ao uso.Criar acesso à API e guardar a chave no ambiente que executa o programa.
CustoSem tarifa por chamada local; há energia, disco e eventual compra de hardware.Faixa gratuita elegível com cotas; modalidade paga cobra conforme modelo e uso.
LimitesMemória, velocidade, tamanho do modelo e janela de contexto.Limites por projeto, modelo e categoria de uso; excesso de cota pode bloquear pedidos.
HardwareRAM e espaço disponíveis precisam comportar o modelo. GPU compatível pode acelerar; não há uma configuração universal.Não exige carregar o modelo no seu PC. Precisa de internet e acesso ao serviço.
PrivacidadeCom modelo local e sem ferramentas externas, os pedidos são processados no computador. Proteja arquivos e logs.Os dados são enviados ao provedor. Tratamento e retenção dependem dos termos, região e modalidade.

No Gemini, os termos distinguem serviços gratuitos e pagos, inclusive no uso de conteúdo para melhorar produtos, com exceções regionais. Não trate a faixa gratuita como ambiente para dados sensíveis. Consulte os termos, as cotas e a cobrança vigente.

No Ollama, local e nuvem são modos diferentes. Confira a FAQ sobre dados, memória e modo somente local e a compatibilidade de hardware. “Gratuito” não significa recursos infinitos.
